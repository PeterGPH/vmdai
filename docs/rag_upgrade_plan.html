Overview

Take the existing pure-BM25 search_docs tool from "competitive on technical text" to "robust across natural-language questions, code identifiers, and partial recall."

scope: docs_search.py only no SDK additions for hard requirement optional dense model (lazy load) backward-compatible tool surface

What stays the same

  • Tool name & signature: search_docs(query, k, scope)
  • Index location: ~/.vmdai/docs_index/
  • Scopes: vmd_ref / user_guide / skills / all
  • Lazy-load on first query (no cost when unused)
  • Output shape: {source, section, score, text}[]

What changes

  • Chunker: heading-aware + code-fence-preserving, with chunk_type metadata
  • Retrieval: BM25  +  dense embeddings  →  RRF fuse  →  cross-encoder rerank
  • Eval: golden queries, Recall@5 / MRR / nDCG@10, regression gate
  • Index files grow: vectors.npy, vector_meta.json alongside bm25.json

Step 2 · Smarter chunking

Current chunker splits on heading + size. Code blocks get clipped; Tcl proc-docs split mid-signature. Fix that.

New rules

  • Markdown: never split inside a fenced ```code``` block
  • VMD Tcl reference: keep proc name { args } { … } as one chunk
  • HTML user-guide: split on <h1..h3>, strip nav, preserve <pre>
  • Add metadata: chunk_type ∈ {prose, code, proc-doc, table} + parent_heading_path
  • Soft cap 800 tokens, hard cap 1200, overlap 80 (was 0)

Step 3 · Add dense embeddings

Sparse BM25 nails identifier queries (NewCartoon, mol new). Dense embeddings nail natural-language questions ("how do I color by secondary structure?").

Choice: model + runtime

OptionSizeInstall costVerdict
fastembed + BGE-small (ONNX)~33 MB1 pip dep, no torchpick
sentence-transformers + MiniLM~80 MB + torch ~700 MBheavyno
hosted (Voyage / OpenAI)0 localAPI key, networkviolates loopback model

fastembed is import-gated and lazy; if absent, runtime falls back to BM25-only and emits a one-line warning.

Storage

  • vectors.npy — float16, shape (N, 384)
  • vector_meta.json — {model, dim, dtype, normalized, built_at}
  • Built by vmd-ai-index --rebuild --with-vectors

Step 4 · Hybrid fusion (RRF)

Reciprocal Rank Fusion is parameter-light, score-scale-agnostic, and beats weighted-sum on most heterogeneous-retriever benchmarks.

Formula

RRF_score(d) = Σ over retrievers r:  1 / (k_rrf + rank_r(d))
                                       (k_rrf = 60, standard)

Take top-30 from each retriever; union; sort by RRF; keep top-30 to feed the reranker.

Step 5 · Cross-encoder rerank

Optional but high-impact. A small cross-encoder (MS-Marco MiniLM-L-6, ONNX, ~90 MB) re-scores the top-30 in one batch.

Trade-offs

With rerankWithout rerank
+0.10–0.15 nDCG@10 typicalsimpler, fewer deps
+200–400ms cold-startp95 stays < 150ms
+90 MB on disk—

Gated by VMD_AI_RERANK=1. Off by default in v1; flip on once step 6 shows real lift.

RiskMitigation

Out of scope (deferred)

  • Per-user feedback loop ("this result was wrong")
