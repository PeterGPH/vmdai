# ChatVMD vs. public agent projects: gap analysis (2026-09-24)

Research behind Part C of `docs/superpowers/specs/2026-09-24-chatvmd-round1-design.md`. Seven agents read 34 public repositories on a fixed 10-dimension rubric; a gap analyst proposed 30 gaps. Section 2 below is the analyst's round-1 proposal **before** verification. Independent verifiers then checked each round-1 item against the cited source files and the edited spec; the outcome is:

| Gap | Verdict | Where it went | Verifier's reason (short) |
|---|---|---|---|
| G2 dangerous-Tcl classifier | shrunk | Spec C1 | A static check can't stop run-time-built command names, so it is framed as an accident guard for literal `exec`/`socket`/`load`/`quit`/protected-path writes; recorded chats show models trying `exec curl`. Categories and warn tiers go to round 2. |
| G1 approval contract | shrunk | Spec C2 | The §1 hook didn't work as specced (the 45 s pickup clock runs until the ack). Fix the ack/deadline/Stop semantics now; decisions, edit and risk fields go to round 2. |
| G4 no half-run commands | shrunk | Spec C3 | The executor half-ran commands with an unbalanced tail, the model got no "still in effect" note, and the recorder dropped partly-applied calls. Hint table deferred. |
| G3 loop guard | shrunk | Spec C4 | Exact call+outcome repeats only (the PyMOL "family" rule misfires on VMD work); tool-less wrap-up at stop and at the turn cap. Oscillation/family rules go to round 2. |
| G5 full output on disk | shrunk | Spec C5 | Round 1's own 6000-character cap would discard output that reaches the model in full today. `read_tool_output` goes to round 2. |

## 1. Where ChatVMD stands

**Where it leads:**
- **Checks answers by computation, not by an LLM judge.**
  - vmdbench checks computed values and rendered pixels through PROBE> introspection. Its bands are set from oracle runs, and a `replay_clean` check confirms runs are repeatable (`vmdbench/verify/checks.py`, `env/scene_state.py`).
  - Others use LLM rubrics (llnl/paraview_mcp dev `eval/eval_claude.yaml`) or expert grading (MDCrow, PMC13033927). ChemCrow's own paper found GPT-4 judges fail.
  - Only ChemGraph's deterministic harness and Biomni-Eval1 are comparable.
- **The only measured semantic-tool gain on a local model.** Semantic tools took a local 14B from 16% to 81%, with provenance verified. MDCrow reports a similar effect, but only on hosted models. None of the 34 repos quantifies this for a local 14–27B model.
- **Every run leaves a replayable domain script** (`.vmdai_runs/<task>/transcript.tcl`, `recorder/run.py`).
  - Coding agents log conversations instead (codex rollouts, gemini sessions). Gemini's rewind docs admit shell side effects are not reverted.
  - Only napari-chatgpt notebooks and MDCrow's `reproduce_simulation.py` come close.
- **Drives the user's live VMD GUI and looks at the real render.**
  - No public VMD MCP server attaches to a live session. OmarArias vmd-mcp aliases its socket controller to a subprocess (`vmd_controller.py:290`), and Alierkn/vmd-mcp spawns `vmd -dispdev text` for every call.
  - ChimeraX's official MCP bridge has no image tool, and MDCrow and DynaMate never feed images back.
- **Round-1 bridge security and bookkeeping are already ahead of in-app peers.**
  - Security: Host/Origin checks and a 128-bit launch token. blender-mcp's README says anyone who reaches its port can run Python, and napari-mcp says "Any local process can invoke these tools".
  - Bookkeeping: an atomic ack against cancel, `executed` reported as yes/no/unknown, `call_key` dedupe, and repair of dangling tool calls.

**Where it trails:**
- **There is no safety gate on unsandboxed Tcl.**
  - Model Tcl auto-runs at `uplevel #0` (`bridge.tcl:482`), with no approval path and no dangerous-command detection.
  - Peers have both: codex (`is_dangerous_command.rs`, `ReviewDecision`), gemini-cli (`ToolConfirmationOutcome`), goose (37 ThreatPatterns), opencode and cline (permission rules and modes), zed (rules users cannot override).
- **It fails badly when the model struggles.**
  - There is no loop detection, and runs end silently at the 28-turn cap. gemini-cli, opencode, cline and OpenHands `StuckDetector` all detect loops, and smolagents asks for a final answer at the step limit.
  - Errors can leave the scene half-changed and name no statement. SWE-agent checks syntax before running and says "NOT executed"; ChimeraX adds `add_error_hints`.
  - Large outputs are silently cut. opencode, gemini-cli and napari-mcp keep the full output and give the model a pointer to it.
- **It has no scene grounding and no undo.** The model guesses molids and rep indices.
  - Grounding: napari-chatgpt adds viewer info to every prompt, goose re-injects turn context (`moim.rs`), and SWE-agent runs `state_commands` after each action.
  - Undo: gemini-cli `/rewind`, cline and opencode checkpoints.
- **Its engineering hygiene lags every other project surveyed.**
  - The repo has no CI, and tests use hand-written fakes (`test_agent_integration.py:188`).
  - The product settings (rescue, compaction, vision, product prompt) are never benchmarked. aider feeds its benchmark results back into model defaults, and zed's eval-cli runs the production agent.

## 4. Considered and rejected

- **G25, opt-in Tcl safe-interpreter mode (later):** the strongest guarantee (VMD ships `scripts/tcl8.6/safe.tcl`), but it breaks `package require` plugins, play scripts and trace callbacks. G2 plus G11 cover a single user's realistic risk first. Revisit once G22 opens the executor to external clients.
- **OS-level sandboxing** (codex `seatbelt_base_policy.sbpl`, gemini `docs/cli/sandbox.md`, Kilo `kilo-sandbox`): the Tcl runs inside the user's VMD GUI process and can't be sandboxed per call. It is a round-1 non-goal.
- **G26, MCP client for RCSB/PDBe** (`rcsb/rcsb-mcp`, `PDBeurope/PDBe-MCP-Servers`): each extra tool schema costs context on a 27B, and the MCP SDK needs Python 3.10+. `mol new <id> type webpdb` plus one RCSB search call covers `fetch_structure`.
- **G27, structured ask_user and checklist tools** (codex `request_user_input_spec.rs`, Kilo `QuestionDock.tsx`): round-1 memory already makes clarifying in prose work, and Qwen-class models may over-use a planning tool. Add only if G23 shows wrong guesses.
- **G28, text-mode tool calling** (continue `systemMessageTools`, OpenHands `non_native_fc.py`): qwen3.8:27b has native tools. Revisit if G9 shows malformed native calls dominate.
- **G29, fallback chains and per-request num_ctx** (OpenHands `fallback_strategy.py`, aider `models.py:1012-1014`): switching models silently breaks provenance (the 72B-under-14B-label incident) and could fall back to a paid provider while the user has no credits. Changing num_ctx also reloads the 27B (§2f `:389`).
- **G30, user hooks, plugin tools and marketplaces** (claude-agent-sdk hooks, cline MarketplaceView): ChatVMD is a single-user plugin, and hooks add attack surface around unsandboxed Tcl. G11 rules, G15 and G16 cover customisation.
- **LLM approval judges** (goose SmartApprove, codex Guardian, gemini Conseca): each adds seconds per call on a local 27B.
- **OpenTelemetry export** (openai-agents, pydantic-ai/logfire): a single-user plugin has no collector. The G7 manifest serves the same purpose.
- **Agent-written memory** (Kilo memory tool, gemini auto-memory inbox): memory the model writes can be written by injected text. G15's human-edited rules come first.
