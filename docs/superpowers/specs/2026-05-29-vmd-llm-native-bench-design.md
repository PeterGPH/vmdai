# VMD-LLM-Native Bench — Design Spec

**Date:** 2026-05-29
**Status:** Approved design (pre-implementation)
**Scope:** A benchmark that measures how *LLM-native* VMD operation is through a ChatVMD-style interface — i.e. how naturally and reliably an LLM can understand the current molecular scene, choose valid actions, execute them through structured tools, verify the result, recover from errors, and export a reproducible workflow.

---

## 1. Motivation & the grounding insight

"LLM nativeness" must mean more than bolting a chatbot onto VMD. For VMD/ChatVMD it means the six dimensions in §3. This benchmark evaluates whether an LLM can *operate VMD as a scientific environment*, not just answer questions about VMD.

The design is grounded in the existing VMD-AI codebase, surveyed before writing. The single most important finding reframes the whole effort:

> **The aspirational framing assumes typed tools; the real system is essentially one free-form-Tcl escape hatch.**
> The actual action surface today (`runtime/vmd_ai_runtime/claude_loop.py:50-242`) is `run_vmd_command` (arbitrary Tcl) + `capture_vmd_snapshot`, plus up to 5 conditional knowledge tools (`search_docs`, `wiki_*`). There are no typed scene-mutation tools. So "actionability" today means "did the model emit valid Tcl," not "did it pick the right typed action."

Other load-bearing facts from the survey:

- **Observability is pull-based and provider-unequal.** No structured scene-state feed exists; the model must choose to run `molinfo`/`$sel num` and read it back. Rendered images are returned to the model **only on `anthropic-direct`** — Ollama/OpenRouter get a text stub. Any cross-model benchmark must normalize this or it is unfair by construction.
- **Three benchmark generations already exist.** Most mature spec: `evals/rag_wiki_suite_v1.json` (`{id, bucket, pdb, prompt, expects[]}`; buckets = lookup/synthesis/operational), scored by **brittle regex idiom-matching** (`scripts/rag_ab_batch.py:65-98`, `IDIOM_PATTERNS`). The wiki/RAG harnesses use a **stub VMD bridge** (every command returns `ok:true`), so the *verification & recovery* dimension is currently **untestable**. Existing baselines (`benchmark_v1/summary.json`, `rag_wiki_results/summary.json`) are **incomplete and HTTP-429-contaminated**.
- **The strongest existing asset is `RunRecorder`** (`runtime/vmd_ai_runtime/recorder/run.py`): atomic `manifest.json` + replayable `transcript.tcl` + snapshots. The new bench builds provenance on this rather than reinventing it.

## 2. Locked design decisions

| Decision | Choice |
|---|---|
| Purpose | **Internal-first, designed to graduate to publishable** |
| Primary axes of comparison | **Models × system-configs** |
| Action surface | **As-is (free-form Tcl) + typed-tool target** (two tracks) |
| Verifier philosophy | **Programmatic state assertions** (run the Tcl, assert on resulting scene state); regex kept only as a non-gating tier-0 smell test; subjective visual/scientific quality routed to an optional human-review lane |
| Execution model | **Live headless VMD** (`vmd -dispdev text`) — makes recovery testable via fault injection |
| Observability contract | **Both tracks** — score self-observation *and* add a typed normalized `get_scene_state` |
| Scoring model | **Gated composite + 6-dimension radar profile** |
| Harness architecture | **Approach B — clean runtime-agnostic spec + thin adapter** (Gym-style "Approach C" can be layered later; not pre-built) |
| Assertion vocabulary | **Closed set, with a documented `custom_check` escape hatch** referencing a reviewed function, used sparingly |
| Gold selection counts | **Regenerated by `oracle_tcl` under a pinned VMD version and stored in the card** (never hand-typed) |

## 3. The six LLM-nativeness dimensions

1. **Scene/context observability** — can the LLM inspect what is loaded (molecules, chains, residues, frames, representations, selections, camera, plugins, trajectories)?
2. **Actionability / structured tool use** — can it act through reliable typed tools instead of hallucinating raw Tcl/Python?
3. **Semantic grounding** — does it understand domain concepts (protein, DNA, ligand, membrane, nanopore, transmembrane region, pore axis, charged residues, protein-DNA interface)?
4. **Feedback, verification & recovery** — can it check whether its action worked and recover (empty selections, missing files, wrong residue names, invalid molecule IDs, bad representation styles)?
5. **Reproducibility & provenance** — can the interaction be exported as a reusable workflow (Tcl, Python, VMD state file, JSON tool-call log, figure recipe)?
6. **Interactive workflow efficiency** — does it reduce user effort (turns, manual corrections, wall time, success rate, correction burden)?

## 4. Architecture (Approach B: clean spec + thin adapter)

One clean seam: a runtime-agnostic benchmark on one side, a thin adapter to ChatVMD on the other. Heavy existing assets (`RunRecorder`, the suite, factorial + seed aggregation) live *behind* the adapter.

```
vmd_ai/vmdbench/
├── tasks/         # THE DATASET — one YAML card per task, pure data, no runtime deps
│     viz/ select/ traj/ recover/ repro/ workflow/
├── spec/          # THE CONTRACT
│     task_card.py     # TaskCard dataclass + JSON-schema validation
│     assertions.py    # closed declarative state-assertion types + custom_check hook
│     dimensions.py    # the 6 LLM-nativeness dimensions + weights
├── env/           # THE ENVIRONMENT BOUNDARY (abstract)
│     base.py          # VMDEnv: reset/observe/act/export/close
│     scene_state.py   # canonical SceneState schema (provider-independent)
│     headless_vmd.py  # HeadlessVMDEnv — drives real `vmd -dispdev text`, parses state
│     faults.py        # fault-injection wrappers (recovery track)
├── adapters/      # THIN GLUE — drive a system-under-test through VMDEnv
│     chatvmd.py       # wraps ClaudeToolLoop / VmdToolBridge (the runtime under test)
│     oracle_tcl.py    # executes reference Tcl directly (baseline / upper bound)
├── verify/        # JUDGE a finished episode
│     runner.py        # replays transcript into a fresh HeadlessVMDEnv, collects SceneState
│     checks.py        # assertion evaluators
│     tier0_idioms.py  # reuse existing IDIOM_PATTERNS as a cheap non-gating smell-test
│     human_review.py  # exports image+rubric packet for expert visual/scientific scoring
├── score/         # scorer.py (gate → 6-dim subscores → composite) + aggregate.py (wraps aggregate_seeds.py)
├── harness/       # run.py (tasks × models × configs × seeds × track) + matrix.py + provenance.py (builds on RunRecorder)
└── report/        # leaderboard.py + profile.py (6-dim radar)
```

### 4.1 The seam — `VMDEnv`

```python
class VMDEnv:
    def reset(self, task: TaskCard) -> SceneState: ...   # load initial_state files/molecules
    def observe(self) -> SceneState: ...                 # structured, provider-independent scene state
    def act(self, action: Action) -> ActionResult: ...   # Action = RawTcl | Typed | Snapshot | Observe
    def export(self, fmt) -> bytes: ...                  # 'tcl' | 'python' | 'vmd_state' | 'json_log'
    def close(self): ...
```

Two choices inside the seam make the benchmark fair and LLM-native:

**(a) `SceneState` is the canonical observation** — derived by issuing introspection Tcl (`molinfo list`, `mol list`, per-rep queries) and parsing into a fixed JSON shape. The adapter feeds this back to **every** provider as the `get_scene_state` tool result, structurally fixing the anthropic-direct-only image problem.

```
SceneState = {
  molecules:       [{id, name, file, num_atoms, num_frames, chains:[...], cur_frame}],
  representations: [{mol_id, rep_id, style, selection, coloring, material, visible}],
  selections:      {<name>: {text, count}},
  display:         {bg_color, projection, axes, depthcue},
  camera:          {center, rotate_matrix, scale},
  rendered_images: [{path, turn}],
  errors:          [{turn, message}],
}
```

**(b) `Action` has two tracks** (the "as-is + typed-tool target"):
- `RawTcl(command, rationale)` — the as-is surface.
- `Typed(name, args)` — the aspirational verbs as real tool schemas: `load_structure`, `create_representation`, `select_atoms`, `align_trajectory`, `render_snapshot`, `export_script`.
- `Snapshot(purpose)` and `Observe()` round out the set.

A task declares which track(s) are permitted (`allowed_interface`); the *same task* can be scored on raw-Tcl vs typed-tools to directly measure the actionability gain.

### 4.2 Adapters

- `chatvmd.py` maps the existing `run_vmd_command`→`RawTcl`, `capture_vmd_snapshot`→`Snapshot`, and registers the typed verbs + `get_scene_state` as additional tools on `ClaudeToolLoop`. It feeds `observe()` back normalized to all providers.
- `oracle_tcl.py` runs expert reference Tcl with no LLM — giving every task a measured **upper bound** and proving the verifier is satisfiable.

## 5. Task cards

Pure declarative data, extending the existing `{id, bucket, pdb, prompt, expects}`. The key change from the original example card: `verifier.checks` becomes a list of **typed, executable state assertions**.

```yaml
task_id: viz_protein_dna_001
category: visualization          # viz | selection | trajectory | recovery | reproducibility | workflow
bucket: synthesis                # lookup | synthesis | operational  (kept from rag_wiki_suite_v1)
difficulty: easy                 # easy | medium | hard
dimensions: [actionability, semantic_grounding, reproducibility]   # primary dims → weighting

initial_state:
  files: [fixtures/1aoi.pdb]     # content-hashed for provenance
  pdb: 1AOI                      # pinned for replay (nucleosome: histones + DNA)
  molecules_loaded: false

allowed_interface: [raw_tcl, typed_tools]   # task is run once per permitted track

user_prompt: >
  Load the structure, show protein as cartoon, DNA as licorice, color each
  chain differently, hide water, set a white background, render to out.png.

verify:
  required:                      # HARD gate — ALL must pass or task = "unsolved"
    - {kind: molecule_loaded,       where: {pdb: 1AOI}}
    - {kind: representation_exists, where: {selection: protein, style: NewCartoon}}
    - {kind: representation_exists, where: {selection: nucleic, style: Licorice}}
    - {kind: selection_visible,     where: {selection: water}, visible: false}
    - {kind: display_property,      where: {bg_color: white}}
    - {kind: file_rendered,         where: {path: out.png, must_be_image: true, min_bytes: 10000}}
  optional:                      # SOFT — feed subscores, don't gate
    - {kind: distinct_chain_colors, where: {min_distinct: 2}}
    - {kind: no_runtime_errors}

observe:
  expect_self_observation: true  # did agent query state before declaring done?
  grounded_claims: true          # final-answer claims match actual SceneState

reproducibility:
  exports: [tcl, json_log]
  replay_clean: true             # re-running exported tcl reproduces the asserted end-state

human_review:                    # optional expert lane for subjective quality
  rubric: [camera_framing, occlusion, color_clarity]
  required: false
```

## 6. The assertion vocabulary (`spec/assertions.py`) — this *is* the verifier

A **closed set** of typed assertions, each a pure-data spec with one evaluator. Closed vocabulary is what makes it defensible/publishable: a reviewer can read all assertion types and trust them. Two families:

**State assertions** (evaluated on `SceneState` after replaying the transcript in a fresh `HeadlessVMDEnv`):
`molecule_loaded`, `representation_exists` (selection+style+coloring+material+visible), `representation_count`, `selection_count` (`expect`/`min`/`max`/`nonempty`, via `atomselect…; $sel num`), `selection_visible`, `display_property` (bg/projection/axes), `frames_loaded`, `camera_changed`, `file_rendered`, `file_exists`, `distinct_chain_colors`, `no_runtime_errors`.

**Episode assertions** (evaluated on the tool-call log):
`tool_used`, `self_observed_before_done`, `recovered_from_error` (within N turns), `grounded_claims`.

**Escape hatch:** `custom_check` referencing a reviewed function in a vetted registry, used sparingly and documented per use. The existing `IDIOM_PATTERNS` regex survives as **tier-0** — a fast pre-filter and extra diagnostic signal that **never gates** a result.

## 7. Taxonomy, difficulty & v1 sizing

| Category | Stresses | Example |
|---|---|---|
| `visualization` | actionability, semantic grounding | the 1AOI card above |
| `selection` | **semantic grounding** | "select pore-lining residues / the protein–DNA interface / charged residues" — graded against **gold atom counts** |
| `trajectory` | actionability, workflow efficiency | align trajectory, per-frame RMSD, contact map, movie export |
| `recovery` | **verification & recovery** | tasks with injected faults (§8) |
| `reproducibility` | **reproducibility & provenance** | "export this scene as a reusable Tcl/Python script + state file" |
| `workflow` | **workflow efficiency**, observability | multi-step "build → adjust → re-render → export" |

**Difficulty** (easy/medium/hard) keys off # required assertions, # steps, semantic ambiguity, and whether recovery is needed.

**v1 size: ~40–50 tasks.** Bootstrap by porting the **14 `rag_wiki_suite_v1` prompts** into cards (they already carry `prompt` + `expects`), then expand to fill the 6×difficulty grid using the pinned PDBs (1HCK, 1IEP, 1HSG, 5IRX, 1AOI, 1ATP, 1UBQ + a TRPV1/pore case). Each task gets an `oracle_tcl` reference solution to prove the verifier is satisfiable and provide an upper bound.

## 8. Recovery track (`env/faults.py`)

Because execution is **live**, real failures can be injected and real recovery measured — impossible with the old stub bridge. Fault taxonomy: `missing_file`, `wrong_resname` (prompt says ligand "LIG" but it's "ATP"), `empty_selection`, `invalid_molid`, `bad_rep_style`. Recovery is scored **0 / partial / full** on: detected the error → diagnosed → issued a corrected action within N turns → still reached the required end-state.

## 9. Scoring model

Each dimension is computed from verifier output + episode log:

| Dimension | Signal source |
|---|---|
| **Observability** | `self_observed_before_done`, `grounded_claims`, and (typed track) whether `get_scene_state` was called *and used* |
| **Actionability** | tool-schema adherence (valid calls, zero rescued-from-prose calls), fraction of intended effects achieved via tools vs. errors; **headline: raw-Tcl vs typed-tools delta** |
| **Semantic grounding** | selection-count accuracy vs **gold**, correct concept mapping (protein/nucleic/water/ligand) |
| **Verification & recovery** | recovery track `0/partial/full`; on normal tasks, observe-after-act |
| **Reproducibility** | required exports producible **and** `replay_clean` |
| **Workflow efficiency** | turns & tool-calls & corrections vs. oracle, errors (correction burden), wall-time (rate-limit-corrected), tokens/cost |

**Gate → composite** (per task `t`, model `m`, config `c`, seed `s`):

```
gate_t      = 1 iff ALL required assertions pass, else 0
raw_{t,d}   = dimension-d subscore in [0,1] from the signals above (only for dims in task.dimensions)
score_{t,d} = gate_t · raw_{t,d}          # unsolved task scores 0 on the dims it gates

solved_rate(m,c) = mean_t gate_t
D_d(m,c)         = mean over tasks where d applies of score_{t,d}
composite(m,c)   = Σ_d w_d · D_d          # default w_d = 1/6 (configurable)
```

Reported three ways: **composite** (leaderboard), **6-dim radar** (profile/diagnosis), **per-category + solved_rate** tables. Seeds aggregated via the existing `aggregate_seeds.py` → mean ± std.

## 10. Provenance & reproducibility (on top of `RunRecorder`)

Each episode flows through `RunRecorder` via the adapter → `.vmdai_runs/<task_id>/` (`manifest.json` + replayable `transcript.tcl` + `snapshots/`). The bench adds:

- **Version pinning in every result record** (current gap): `model_id` + `provider` + **model version/snapshot string**, `seed`, `temperature`, **VMD version**, fixture content-hashes, `vmdbench` version, prompt hash.
- **Rate-limit isolation** (fixes 429-contaminated baselines): episodes dying on HTTP 429 / provider errors → `status: infra_error`, **auto-retried with backoff up to K times**; if still failing they are **excluded from scoring** and reported separately — never counted as task failures.
- **`replay_clean` check**: `verify/runner.py` re-executes the exported `transcript.tcl` in a fresh `HeadlessVMDEnv` and confirms the asserted end-state reproduces — both the reproducibility hard-signal and a determinism check on the verifier itself.

Per-episode result JSON:
```
{task_id, model, config, seed, interface_track,
 env_versions:{vmd, vmdbench, os}, status, gate,
 assertions:[{kind, where, passed, observed}],
 dim_scores:{}, efficiency:{turns, tool_calls, corrections, wall_s, tokens},
 recovery, exports:{}, replay_clean, recorder_dir}
```
Reports derive entirely from these → re-reportable without re-running.

## 11. The run matrix (`harness/run.py` + `matrix.py`)

Factorial: **tasks × models × configs × seeds × interface-track.**
- **models**: provider registry (anthropic-direct, openrouter, ollama), each pinned to a version string.
- **configs (arms)**: extend the existing `none/rag/wiki/both` with a **typed-tools** axis — reusing `rag_wiki_ab.py`'s arm machinery behind the adapter.
- **seeds**: N (default 3) for variance.
- **interface-track**: `raw_tcl` vs `typed_tools` per task's `allowed_interface` → the headline actionability delta.
- **oracle**: `oracle_tcl` runs once per task = upper bound + verifier-satisfiability proof.

## 12. Build order (each step yields usable internal signal before the next)

1. `spec/` (TaskCard + assertions + dimensions) + port the 14 `rag_wiki_suite_v1` prompts to cards.
2. `env/headless_vmd.py` + `scene_state.py` + `oracle_tcl` adapter → prove the verifier is satisfiable on the 14.
3. `verify/` (runner + checks + tier0) + `score/scorer.py` → first scored numbers, one model.
4. `adapters/chatvmd.py` (raw-Tcl track) + `harness/run.py` + provenance (version pinning + 429 isolation) → first model×config runs.
5. `typed_tools` track + `get_scene_state` observation + recovery track (`faults.py`).
6. `report/` (leaderboard + radar) + seed aggregation + `human_review` export.
7. Hardening + docs + expand dataset to ~40–50 → publishable.

## 14. Risks & open questions

- **Headless VMD fidelity:** rep/state introspection in `-dispdev text` mode must reproduce what interactive VMD shows; needs validation on the 14 seed tasks early (build step 2).
- **VMD version pinning for gold counts:** counts are regenerated from `oracle_tcl` under a pinned VMD; bumping VMD requires regenerating and diffing gold values.
- **Cost/rate limits:** full matrix (tasks × models × configs × seeds × tracks) is large; harness must support smoke subsets and respect backoff. 429-isolation prevents contamination but not slowness.
- **Typed-tool layer scope:** the typed verbs must be implemented in the `chatvmd.py` adapter (build step 5) before the typed track can run; until then only the raw-Tcl track produces numbers.
- **Grounded-claims scoring:** comparing free-text final answers to `SceneState` may need an LLM-judge or a constrained claim format; start with a constrained format to keep it deterministic.
- **C (Gym-style) deferral:** the `VMDEnv` action interface is shaped to *allow* a richer typed action space later, but no episode/step-level RL machinery is built in v1.
