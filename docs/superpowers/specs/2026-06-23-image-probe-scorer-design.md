# Reference-free image probes for vmdbench — design spec

- **Date:** 2026-06-23
- **Branch:** vmdbench-design
- **Author:** Peter
- **Status:** approved design, pre-implementation

## Motivation

vmdbench verifies *analysis* correctness directly (`scalar_within` compares a computed
value to an oracle), but *visualization* tasks are still checked only structurally:
`representation_exists` confirms the right representation/style/color command took effect
in the scene graph. It does **not** confirm anything about the rendered picture. The
documented failure mode — an agent that "renders" a scene containing **zero
representations**, or runs `mol modcolor Chain` and produces a **single-color** image —
passes a structural or text rubric while the picture is wrong.

This is the visualization analogue of the project's central thesis ("completion is not
correctness"). We want to measure whether the *rendered image* is actually non-empty and
correctly colored, **deterministically** — explicitly **not** with a vision-model judge,
which would undercut the thesis. The measurement must be reproducible and reviewer-defensible,
i.e. it must live in the same gated, oracle-calibrated verifier as the scalar checks.

## Goals

- Add two **reference-free** (inspect the agent's own render; no oracle image, no
  camera matching) image checks as **first-class vmdbench assertion kinds**, so they feed the
  existing gate, per-dimension scoring, composite, and `replay_clean` reproducibility check.
- **Pure-stdlib**, deterministic, fast. Preserve vmdbench's zero-dependency core (Pillow optional only).
- Calibrate pass/fail bands from the oracle render, the same workflow as `scalar_within` /
  `select_water_count` (gold regenerated by the oracle, never hand-typed).

## Non-goals (v1 — explicitly deferred)

- Oracle-image comparison (silhouette IoU, SSIM, LPIPS) and any camera normalization.
- Projected-coordinate visibility probes (would require dumping per-atom coords from the env
  and replicating VMD's camera projection).
- Any vision-model / LLM judge.
- New required dependencies (numpy/skimage/torch). Pillow is an **optional** accelerator / PNG path only.

## Design overview

Both checks read the rendered image from `ctx.workdir / where["path"]` — the same place
`file_rendered` reads it. The image is produced by the task's/oracle's own
`render TachyonInternal <path>` (TachyonInternal is a software raytracer that works headless;
`render snapshot` needs a GL context and yields the invalid stub `file_rendered` already guards).

Because the checks are reference-free, **no changes are needed to the env, `scene_state`,
the scorer, the runner, or the CLI.** The work is: a decode/probe module, two evaluators,
and registering them in the assertion vocabulary + dimension map.

Like any vmdbench assertion, a card places these in `verify.required` (they then **gate** the
score — failing one zeros the composite, exactly as the gate already works) or in
`verify.optional` (scored into their dimension but non-gating). No special-casing in the runner.

## Component 1 — `image_foreground`

Is the render non-empty? (Catches the empty-scene-saved-as-valid-image failure.)

```yaml
- {kind: image_foreground,
   where: {path: out.tga, min_coverage: 0.05, max_coverage: 0.98,
           background: white, check_background: true}}
```

- **`path`** (required): image file, relative to the run workdir.
- **`min_coverage`** / **`max_coverage`** (optional): bounds on *foreground coverage* =
  fraction of pixels whose color distance from the background exceeds `tol`. `min_coverage`
  defaults to a small value (≈0.02) so "essentially blank" fails; `max_coverage` defaults to 1.0.
- **`background`** (optional): expected background color (name or `#rrggbb`). If omitted, the
  background is **auto-detected** as the median color of the image border pixels.
- **`check_background`** (optional bool): if true, additionally assert the detected border color
  matches `background` within `tol` — the rendered analogue of `display_property{bg_color}`.
- **`tol`** (optional): per-pixel color match tolerance, 0–1 scale (default ≈0.06).
- **`observed`**: `{coverage, background_rgb, width, height}`.
- **Fails** when: file missing, undecodable, zero-dimension, coverage outside band, or
  `check_background` mismatch.

## Component 2 — `image_palette`

Did the requested colors actually render? (Catches "ran the color command but it came out one color".)

```yaml
- {kind: image_palette,
   where: {path: out.tga, min_distinct: 2, expect_colors: [red, blue], min_fraction: 0.03}}
```

- **`path`** (required).
- **`min_distinct`** (optional int): require at least N distinct **dominant foreground colors**.
  Dominant colors are found by excluding the background, **coarsely quantizing** the remaining
  foreground pixels in RGB (a small grid, ≈3 levels/channel by default), and keeping buckets whose
  share of foreground ≥ `min_fraction` (default ≈0.03). Coarse bucketing makes one shaded object
  land in 1–2 buckets, so the count reflects genuinely distinct colors, not shading gradients.
- **`expect_colors`** (optional list): named (`red`,`blue`,`green`,`cyan`,`orange`,`yellow`,
  `purple`,`magenta`,`pink`,`white`,`gray`,`black`) or `#rrggbb` colors that must each be present
  among the dominant colors. Matching is **shading-robust**: chromatic targets match by **HSV hue
  proximity** (default ±25°); achromatic targets (white/gray/black) match by lightness among the
  achromatic dominant colors. (This handles VMD's chain palette, where e.g. chain colorID 2 is gray.)
- **`min_fraction`**, **`background`**, **`tol`** (optional): as above.
- At least one of `min_distinct` / `expect_colors` must be present (enforced at card-load).
- **`observed`**: `{distinct, dominant: [[r,g,b], frac]…, background_rgb}`.
- **Fails** when: file missing/undecodable, `distinct < min_distinct`, or any `expect_colors` entry
  not matched.

## Component 3 — `vmdbench/env/image_probe.py` (new, pure-stdlib)

- **Decode**: TGA uncompressed (type 2) **and** RLE (type 10), handling BGR→RGB and the
  bottom-to-top row order (logic ported/adapted from the runtime's `image_utils.py`). Returns a
  pixel buffer + `(width, height)`.
- **Downsample**: integer striding so the long edge is ≤ ~200 px before any per-pixel work — keeps
  the pure-Python probes fast on 1000²+ renders. Coverage/palette are statistical, so striding is fine.
- **PNG / other formats**: if Pillow is importable, use it; otherwise return a decode failure with a
  clear message ("render TGA via TachyonInternal, or install pillow"). VMD's native render is TGA, so
  the core path stays stdlib.
- **API** (consumed by the evaluators):
  - `load_pixels(path) -> (pixels, w, h)` (raises a typed decode error the evaluators convert to a failing `CheckResult`).
  - `detect_background(pixels, w, h) -> (r,g,b)` (border median).
  - `foreground_coverage(pixels, bg, tol) -> float`.
  - `dominant_colors(pixels, bg, tol, min_fraction) -> [((r,g,b), frac)…]`.
  - small helpers: `parse_color(name_or_hex) -> (r,g,b)`, `rgb_to_hsv`, color-name → RGB table.

## Integration points

- **`vmdbench/verify/checks.py`**: two new `@_register("image_foreground")` /
  `@_register("image_palette")` evaluators, reading `ctx.workdir / where["path"]` and returning
  `CheckResult(kind, passed, observed, where)`. They wrap decode failures into a failing result
  (never raise).
- **`vmdbench/spec/assertions.py`**: add both to `KNOWN_KINDS`; `_REQUIRED_WHERE` requires `path`
  for both; `image_palette` additionally requires at least one of `min_distinct` / `expect_colors`.
- **`vmdbench/spec/dimensions.py`**: `KIND_DIMENSIONS` maps `image_foreground → actionability`
  (the action produced a real, non-empty artifact) and `image_palette → semantic_grounding`
  (colors map to the requested semantics — consistent with `distinct_chain_colors`).
- **No changes** to `env/headless_vmd.py`, `env/scene_state.py`, `score/scorer.py`,
  `verify/runner.py`, or `cli.py`.

## Render convention & calibration

- Viz oracles that carry image checks render with `render TachyonInternal <path>` to the same
  `path` the card asserts. (Document the TachyonInternal requirement in the oracle header.)
- Bands are calibrated, not guessed: run `python -m vmdbench.cli score-oracle <card> <oracle>`,
  read the `observed` coverage / dominant colors off the gold render, and write
  `min_coverage` / `min_distinct` / `expect_colors` around them — identical to how
  `scalar_within` tolerances and the `select_water_count` expectation are set from the oracle.
- **Reproducibility**: TachyonInternal is deterministic, so the same scene re-renders identically
  and `replay_clean` stays green. Image statistics are **not** added to `_scene_fingerprint`
  (the fingerprint stays scene-graph based); the image checks simply gate-pass on both replay runs.

## Error handling

Every failure path yields a failing `CheckResult` with a descriptive `observed`, never an
exception that aborts the run:
- missing file → `"image not found: <path>"`
- unsupported/undecodable format (no Pillow) → `"cannot decode <fmt>; render TGA or install pillow"`
- zero-dimension / empty image → coverage 0 → fails `min_coverage`
- all-background render → coverage 0 and `distinct == 0` → both checks fail (the empty-scene case)

## Testing (`vmdbench/tests/`)

- **`test_image_probe.py`** (no VMD needed; synthesize tiny TGAs in-memory):
  - white-bg image with a colored blob → coverage within band, `distinct ≥ 1`;
  - all-white image → coverage ≈ 0 → `image_foreground` fails (the empty-scene guarantee);
  - two-color blob → `distinct == 2`; `expect_colors:[red,blue]` matches under shading jitter;
  - achromatic case: blue + gray blobs on white → both counted as distinct (chain-palette edge case);
  - TGA decode round-trip for type-2 **and** RLE type-10.
- Extend **`test_assertions.py`** (new kinds validate; `image_palette` without `min_distinct`/`expect_colors` rejected), **`test_dimensions.py`** (mapping), **`test_cards_load.py`** (a card using the new kinds loads).
- One **VMD-gated** end-to-end test (skips if the VMD binary is absent): run the demo viz oracle, probe its real render.
- **Demo card + oracle**: extend `viz_color_element_1crn_001` to `render TachyonInternal` and assert
  `image_foreground` + `image_palette`; add one additional viz card exercising `min_distinct`
  (e.g. color-by-chain on a multi-chain structure). Bands calibrated from the oracle.

## Risks / open considerations

- **TGA RLE decode correctness** — mitigated by the round-trip decode test.
- **Headless TachyonInternal availability** on the dev/CI machine — the e2e test skips when VMD is
  absent; the unit tests cover the probe logic without VMD.
- **Quantization/threshold defaults** (coarse-RGB grid, `min_fraction`, hue tolerance, saturation
  cutoff) may need tuning per task — that is exactly what the oracle-calibration workflow is for, and
  the defaults are pinned by tests.
- **Achromatic chain colors** (gray) — explicitly covered by a test so `min_distinct` doesn't undercount.
