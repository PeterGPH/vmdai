Closing the completion–correctness gap: three interventions

How proactive reference injection, Tcl pre-validation, and semantic measurement tools take a baseline VMD agent from 56% to 97% correct.

Author: Peter  ·  Model: Qwen2.5-72B-Instruct-AWQ (local vLLM)  ·  Arm: config_local.json ("improved")  ·  Date: June 23, 2026

In one paragraph

The baseline agent completes most tasks but is correct far less often — it confidently reports wrong numbers, hangs on malformed Tcl, and mis-writes VMD's measurement syntax. Three targeted interventions, each motivated by an observed failure mode, raise correctness to 97% on the analysis suite and collapse the completion–correctness gap to roughly zero. The decomposition matters as much as the headline: only one of the three actually generalizes.

1 Proactive reference injection

Fixes: idiom-level errors (self-RMSD recomputation, mol load cif, the contacts-is-not-a-number bug).

Mechanism. At setup(), if the arm sets inject_reference_path, the file is read and appended verbatim to the system prompt — no tool call, no retrieval, the knowledge is guaranteed in context:

ref_path = self.config.get("inject_reference_path")
if ref_path:
    with open(os.path.expanduser(ref_path)) as fh:
        ref = fh.read()
    self._system_prompt += "\n\nVMD TCL REFERENCE — use these exact, correct idioms:\n" + ref

integrations/scivisagentbench/vmd_ai_agent.py:217–225

What gets injected. A 54-line cheat-sheet where, in its own words, "each entry exists because an agent got it wrong; the right form is given first." The entries map directly onto the baseline's observed failures:

  • Load with mol new file.cif — not mol load cif ("Cannot read file of type cif").
  • Self-RMSD is exactly 0.0 — report 0.0, do not recompute or align.
  • measure contacts returns two parallel lists; the count is [llength [lindex $result 0]] — "the result itself is not a number."
  • Coordinates are {x y z}, not {x y z] (the unbalanced-brace hang).

Why injection and not RAG. The rag / ragforce ablation arms showed the model won't call a docs_search tool even when explicitly instructed to. Injection sidesteps that entirely, separating "won't retrieve" from "can't use it." This is the only one of the three interventions that generalizes in the held-out test — and only on the idioms the cheat-sheet actually teaches (3-atom angle 4→6, dihedral 3→6).

2 Tcl pre-validation

Fixes: silent interpreter hangs that burn the whole task's time budget.

Mechanism. Before any command reaches VMD, the bridge checks that its braces and brackets balance. If not, it is rejected instantly with a fix-hint instead of being sent:

if not _tcl_is_complete(command):
    return {"ok": False, "output": "",
            "error": "incomplete Tcl: unbalanced braces/brackets/quotes — not "
                     "executed. Fix the brackets (e.g. `[list $i $j]`, coords as `{x y z}`)."}

integrations/scivisagentbench/subprocess_vmd_bridge.py:171–174

The check itself is a pure-Python balance counter — no real Tcl interpreter (a tkinter Tcl interp is thread-affine and would abort the agent's worker thread):

def _balanced(s):
    brace = brack = 0; esc = False
    for ch in s:
        if esc: esc = False
        elif ch == "\\": esc = True
        elif ch == "{": brace += 1
        elif ch == "}": brace -= 1
        elif ch == "[": brack += 1
        elif ch == "]": brack -= 1
        if brace < 0 or brack < 0: return False
    return brace == 0 and brack == 0

subprocess_vmd_bridge.py:431–449

Why it matters. An unbalanced command like {x y z] does not error — the Tcl interpreter assumes the statement is unfinished and waits for more input, so the bridge blocks until the per-command timeout. A single malformed line could stall the entire task. Rejecting it immediately lets the model recover on the next turn; a companion timeout handler also restarts VMD fresh so a hang can't poison the rest of the session. The "improved" arm additionally doubles the timeouts (vmd_timeout 45→90 s, task_timeout 360→600 s).

3 Semantic measurement tools

Fixes: wrong measurement syntax — the model chooses the operation, the harness writes the Tcl.

Mechanism. When enable_semantic_tools is on, the agent gains two typed tools — vmd_measure(metric, selection) and vmd_represent(style, color, selection) — backed by a fixed table of correct Tcl. The model supplies only the operation and selection; it never writes the brittle syntax itself:

_METRIC_TCL = {
    "rgyr":      ('... [measure rgyr $__s] ...',                 True),
    "sasa":      ('... [measure sasa 1.4 $__s] ...',             True),
    "natoms":    ('set __v [molinfo top get numatoms]',          False),
    "nresidues": ('... [llength [lsort -unique [$__s get residue]]] ...', True),
    "ca_dist":   ('... [measure bond [list ...first... ...last...]]',   True),
    "rmsd_self": ('... [measure rmsd $__s $__s] ...',            True),
}

subprocess_vmd_bridge.py:212–220  ·  executed via _measure() / _represent(), which also pass through pre-validation (#2). vmd_represent validates style/color against allow-lists.

The catch — and why the held-out study exists. This is the strongest correctness lever, but only for the six operations in the table. Those six keys are the benchmark's analysis metrics — so on covered tasks "the tool does the task by construction." Strip the covering tools and correctness falls to 67%; off their coverage, the inject arm and the full +tools arm are identical (the tools add nothing they don't cover).

  • Completion 65→97 is mostly #2 — pre-validation removes the timeout-hangs and the doubled timeouts give the slow local GPU room. This is about robust execution, not getting answers right.
  • Correctness 56→97 is mostly #3 (the tool is the task for covered metrics) plus a little #1 (injection fixes idiom bugs like self-RMSD). The held-out table proves it: drop #3 and correctness falls to 67%, with #1 supplying the only genuine generalization.

Two flags for the writeup

#2 is baked in, not ablated. _tcl_is_complete is unconditional in the subprocess bridge — every arm uses it, including the "none" baseline. So the held-out table (none / inject / +tools) does not actually isolate pre-validation, yet the paper lists it as one of three interventions. Either add a --no-prevalidate ablation, or reframe #2 as a baseline-robustness fix rather than a measured arm.
Report correctness given completion. Because #2 lifts completion while #1/#3 lift correctness, a single "56→97" hides the two mechanisms. Adding a correct-given-completed column cleanly separates "answers more often" from "is right when it answers."
